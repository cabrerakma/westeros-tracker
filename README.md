# Westeros Tracker

A browser map of Westeros for tracking which faction holds which of 42 territories in a friends' wargame campaign, with a per-territory battle history. One game master (GM) edits; everyone else watches. Full design: [westeros-map-spec-v2.md](westeros-map-spec-v2.md).

**Status:** map, GM editing and battle history done. Next: export/import and sharing, then live sync.

## Run it

Requires Node 20+.

```sh
npm install
npm run dev        # start the app
npm test           # Vitest
npm run validate   # check the data files
npm run check-colors   # color-blind / grayscale check of faction colors
npm run generate   # rebuild territory shapes + adjacency (overwrites territories.geo.json)
npm run build      # validate + typecheck + static build into dist/
```

`npm run build` runs `validate` first, so bad data fails the build.

## Data files (all in `src/data`)

| File | What it holds |
| --- | --- |
| `factions.json` | The 13 starting factions (id, name, color, glyph). `neutral` ("Unclaimed") is built in and must stay. |
| `regions.json` | The 11 regions and their label positions (generated). |
| `territories.json` | The 42 territories: seat (real castle position), tier, region, home faction, adjacency (derived). |
| `glyphs.json` | Faction glyphs. **Placeholders for now**; final original art arrives in M4. |
| `scenarios/*.json` | Starting holders. `war-of-five-kings.json` and `blank.json` ship. |
| `territories.geo.json` | Territory shapes as SVG paths (plus region outlines and sea links). Generated by `npm run generate`; you can hand-edit it, but re-running the script overwrites it. |

JSON can't hold comments, so the rules live here:

- **Add or recolor a faction:** edit `factions.json` (and the same entry inside each scenario's `factions` list). Colors must be `#RRGGBB`, the glyph must exist in `glyphs.json`.
- **Home faction vs holder:** a territory's `homeFaction` is its original owner; the holder comes from the scenario. If they differ (and the holder isn't `neutral`) the map shows an "occupied" ring in the home faction's color.
- **Adjacency** must be symmetric (`validate` checks it). The list in `territories.json` is a hand-written starting point; M1 re-derives land edges from the map shapes and keeps sea links and the Wall by hand.
- **Add a scenario:** copy `scenarios/blank.json`, give it a new `id`, set every territory's holder, then run `npm run validate`.

## Assumptions and decisions

- Tully and Arryn are not factions. The Riverlands start held by Stark (home faction Stark, so a captured Riverlands territory shows a Stark ring). The Vale starts `neutral`. The Dreadfort's home faction is Bolton.
- Bolton is light pink (`#F0B8C8`), lightened from the first draft because it matched Stark's luminance.
- `check-colors` is advisory. Under grayscale some pairs (for example Martell vs Free Folk) look alike by color alone, which is why every faction also has a glyph. No pair fails under red-green simulation at the default threshold.
- The GM passcode will be hard-coded as `password234` in M5 (front end and database function). Anyone who reads the page's JavaScript can find it, so this stops casual edits only. To change it, edit both places.
- The hosted site is reachable by anyone with the URL. It ships with `noindex` and `robots.txt` blocking crawlers; share the link only with your group.
- Dev dependencies are pinned to Vite 5 and Vitest 2 because the installed Node is 20.11. `npm audit` reports advisories about the dev server only; they do not affect the built site.

## How the map is built

The geography comes from real map data, trimmed into `scripts/source/westeros-source.json` by `scripts/extract-source-map.mjs` (a one-off; you do not need the original download again). `npm run generate` then:

1. Projects the political regions into a 1000-wide map space, merges the Gift into the North, cuts a thin strip along the Wall (The Wall region) and crops everything north of it (Beyond the Wall).
2. Adds a strip of the Essos west coast for the Free Cities (Pentos and Braavos).
3. Splits each region with a Voronoi diagram of its castle seats. Islets with no castle go to the nearest castle of the region (Skagos, Skane and the whole Vale are the exception: they are drawn as unselectable scenery (`SCENERY_BOXES` and the `scenery: true` region)).
4. Derives land adjacency from shared boundaries and adds sea links for islands and the Narrow Sea crossings.

Seats are real castle positions from the source data. A few have no source location and were placed by hand: Frostfangs, Hardhome, the Fingers, the Arbor, Bear Island. Casterly Rock uses Lannisport's position. Seats that fall just off the coast are moved onto land. To tune anything, edit the tables at the top of `scripts/generate-territories.mjs` (`SEAT_SOURCE`, `SEA_LINKS_EXTRA`, `FORCE_NOT_ADJACENT`) and run `npm run generate`. Re-running overwrites `territories.geo.json`, `territories.json` seats and adjacency, and region label positions.

## Using it

- **View mode** is the default: anyone can look, click territories and read the notes. Nothing can be changed.
- **GM mode** (top bar) asks for the passcode, `password234`. It is set in `src/state/gm.ts` and is checked in the browser only, so it stops casual edits, not someone who reads the page's code.
- In GM mode: pick a faction in "Who holds what", then click territories to give them to it (Esc stops). Or open a territory and use the "Held by" dropdown. Add notes there too.
- **Undo / Redo** in the top bar, or Ctrl+Z and Shift+Ctrl+Z. The change log ("Recent changes") is never rewritten: undoing adds a line.
- **Battles:** open a territory (the Territory tab) to see its battle history, with "fought N times" and "changed hands N times". In GM mode, "Record a battle": date, attacker and defender, the players on each side, the outcome (captured, repelled, draw) and a note. A capture can give the territory to the attacker in the same step. **Edit** and **Delete** fix a bad report; they change only the history, and if the battle had captured the territory you are asked whether to change the holder back. Deleting is the easy way out for a report that is too wrong to fix.
- **Reset the map** (bottom of the sidebar, GM mode): choose a starting position, confirm, and it downloads a backup file of the current map first. The reset can still be undone, and the log is kept.
- Everything is saved in this browser automatically. Until live sync is built, each browser has its own copy of the map.
